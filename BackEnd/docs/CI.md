# Backend CI

Workflow: `.github/workflows/backend-ci.yml` (at the root of the BackEnd branch).

GitHub Actions runs on pushes to `BackEnd`, pull requests targeting `BackEnd`,
and manual dispatch. Branch names are case-sensitive. New commits cancel an older
run for the same branch or pull request.

The Ubuntu runner installs .NET 10, restores and builds `FarmMonitoring.slnx` in
Release, then runs both unit and integration tests. PostgreSQL 18 runs as an
isolated service container. `TEST_POSTGRES_CONNECTION` points only to that service;
the integration fixture creates unique databases, applies migrations and removes
the databases afterward. The disposable CI account can create databases.

No repository secrets, local user secrets, production database, SMTP account or
device credentials are required. Test authentication keys are generated by the
fixtures. This workflow performs CI only; it does not deploy or migrate an
application database.

Test failures fail the job. TRX reports are uploaded even after a failing test
step and kept for 14 days. If restore/build fails before tests run, there may be
no test report; inspect that step's log in Actions.

Commit and push the workflow with the backend code it tests to activate push/PR
runs. Manual dispatch through the Actions UI requires the workflow to exist on
the repository's default branch. Branch protection can optionally require the
`Build and test (.NET 10 / PostgreSQL 18)` check; configure that in GitHub after
the first run. This change does not modify repository protection settings.

For Windows local verification using a temporary PostgreSQL instance:

```powershell
.\scripts\Test-Postgres.ps1 -PostgresBin 'D:\IDECode\PostgreSQL\18\bin' -Configuration Release
```

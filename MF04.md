# MF-04 frontend

Backend contract and three-role demo: [BackEnd/MF04.md](https://github.com/ductrong1710/GFA26SE110/blob/BackEnd/MF04.md), [API.md](https://github.com/ductrong1710/GFA26SE110/blob/BackEnd/API.md).

- Crop season details open the existing report form with Farm/Zone/Crop/Season prefilled, including completed seasons. Standalone reports remain available. New UI submissions require observation time; local datetime inputs serialize to UTC ISO timestamps with an offset. Old reports display **Not recorded**.
- Season choices are paged and filtered by farm/zone/current owner. Changing scope clears season/channel references. API errors retain entered values and evidence.
- Detail uses server `allowedActions` and `canReadEvidence`; unclaimed Engineer inbox does not fetch images/journal/readings/alerts. Assigned Engineers read evidence only through report child APIs. Unknown/error/valid data are distinct; actual zero remains zero.
- Default evidence window: observation minus7 days to plus1 day; explicit inclusive range up to31 days; no observation means clearly labelled all-time legacy context. Care images and history are separately paged/bounded.
- Admin assigns active Engineers. Owner feedback supports acknowledgement/agreement/questions/care/improvement, optional images and existing season activity. Closed cases accept non-improvement review requests; only the assigned Engineer reopens with reason. Case actions do not complete a season.
- Conflict reload preserves the draft; the user compares history and explicitly accepts the latest revision before resending.
- MF-03 referral opens the existing incident flow in another tab, then allows refreshing and linking a permitted incident. MF-02 video referrals visibly remain pending integration. AI is absent until OD-02 approval; manual advice remains available.

Changed UI: CropReportForm, CropSupportDetail, CropSupportEvidence, CropSupportPage, CropSeasonsPage and permission config. Existing api.request/useApiQuery, evidence components and DataTable pagination are reused.

Verification: `npm run lint`, `npm test`, `npm run build`. On resource-constrained hosts run JSX tests with `vitest run tests/*.test.jsx --environment jsdom --maxWorkers=2`. The MF-04 browser workflow checks out this frontend commit and the current BackEnd branch, logs the exact backend SHA, starts a disposable PostgreSQL18/API, then runs `e2e/crop-support.spec.js` in Chromium. It covers season/journal intake, Admin assignment, information exchange, recommendation, linked feedback, close/review/reopen, unchanged season and Swagger descriptions. No production data is used.
